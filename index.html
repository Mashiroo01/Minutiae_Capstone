Connected System Features

Applicant Screening

Run live police clearance screening from the applicant page using name, age, sex, and fingerprint verification only when a demographic hit is found.

Data Privacy Consent

The applicant workflow is locked until the mandatory Data Privacy Act consent notice is accepted for the current page session.

Biometric Matching

Fingerprint verification uses NIST Bozorth3 matching and keeps possible biometric hits in a neutral processing state on the applicant side.

Application History

Every application is recorded with timestamps, status updates, fingerprint verification status, and append-only audit history.

Protected Admin Access

Admin and super admin access is authenticated, role-restricted, and separated so sensitive fingerprint match details stay protected.

Super Admin Review

Restricted fingerprint hits are surfaced only to the super admin for manual review, decision logging, and final action handling.

How The System Works

1

Applicant Opens The Screening Page

The applicant workflow begins from the screening page, where personal data entry stays locked until the privacy consent notice is accepted.

2

Demographic Screening Runs First

The system checks the applicant's name, age, and sex against stored criminal records before asking for fingerprint verification.

3

No Demographic Hit Means Approved

If no demographic hit is found, the application is automatically approved and counted in the approved statistics.

4

Fingerprint Verification Runs Only When Needed

If a demographic hit appears, the applicant fingerprint is captured or uploaded and then compared against relevant criminal biometric records.

5

Final Status Is Controlled By The Match Result

No fingerprint match means approved. A possible fingerprint hit stays in processing for restricted review. A confirmed fingerprint match leads to rejection.
